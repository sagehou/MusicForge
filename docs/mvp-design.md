# MusicForge MVP 设计基线

[English](mvp-design.en.md) · **简体中文**

此文件记录确认的产品行为，作为实现和验收基线。部署与 CI 说明见[中文 README](../README.zh-CN.md)。中英文设计文档应同步更新。

开发环境与发布约束见 [AGENTS.md](../AGENTS.md)。

## 目标与范围

MusicForge 是自托管的音乐流媒体版本构建工具：Lidarr 管理 FLAC 源库，MusicForge 调用 ffmpeg 生成播放产物，Navidrome 读取产物提供播放。

- FLAC 源库是音乐内容和标签的事实来源；输出歌曲和封面由程序生成。
- 单机优先、Docker 部署、简单可靠、长期可维护。
- MVP 只维护一组源库与输出库，一个输出库使用一套当前编码配置。
- 第一阶段不实现云同步、rclone、多节点 worker、多用户权限、多租户或插件系统。
- 数据库使用 SQLite；不引入 Kubernetes、Redis 或 PostgreSQL。

## 单容器架构

- 后端采用 Go；编码工作由 ffmpeg 子进程执行。
- 一个 `musicforge` 容器运行一个 Go 应用进程。
- 同一应用提供 Web/API，并在后台执行扫描、转换、文件管理与集成任务。
- API 创建持久化任务，不在请求处理过程中直接执行 ffmpeg。
- SQLite 保存库索引、产物状态、任务队列、账号和网页设置。
- React 构建产物随应用发布；运行镜像包含 ffmpeg 和 ffprobe。
- 保持清晰的功能划分，采用标准库与必要的成熟依赖。

## 挂载与文件管理范围

- `/config` 读写挂载到 Docker 宿主机本地磁盘，包含数据库及其 WAL 等状态文件。
- FLAC 源目录独立只读挂载。
- 转码输出目录独立读写挂载，音乐文件的写入、替换、搬迁和删除由后台任务执行。
- Navidrome 对应音乐库只读挂载同一个宿主机输出目录；容器内路径名称可以不同。
- 源目录和输出目录分开，任务路径必须校验在配置的根目录范围内。

输出目录是 MusicForge 专用目录：首次初始化使用空目录，后续管理自己生成并登记的产物。未登记文件不自动覆盖或删除，路径冲突明确报错。

输出沿用源库的相对目录与文件名，仅替换扩展名。例如：

```text
source/Artist/Album/01 - Title.flac
output/Artist/Album/01 - Title.opus
```

## 编码配置

支持 Opus 和 MP3，均可选择 VBR 或 CBR。选择一个格式生成一个输出库，不同时生成两套库。

| 编码 | 编码器 | 推荐模式 | 推荐值 |
| --- | --- | --- | --- |
| Opus | `libopus` | VBR | 192kbps 平均目标 |
| MP3 | `libmp3lame` | VBR | V2 质量档位，实际平均码率随内容变化，通常约 190kbps |

- 初始默认编码为 Opus，使用 VBR、192kbps。
- 两种编码选择 CBR 时，默认码率为 192kbps。
- MP3 VBR 显示质量档位设置；Opus VBR 显示平均目标码率；CBR 显示固定码率。
- UI 显示推荐值，并提供恢复推荐值的操作。
- 修改编码格式、模式、码率或质量参数后，已有不匹配产物标记为待重建，等待手动启动重建。
- 待重建与源文件已删除的过期状态分开展示。

## 扫描与增量构建

扫描 FLAC，读取 Artist、Album、Title、Track number、Disc number、metadata、文件大小和修改时间，保存到 SQLite。

日常扫描采用快速检查：

1. 首次发现文件，读取标签并计算完整文件内容哈希。
2. 大小或修改时间变化，重新读取并比较内容哈希。
3. 两者未变则跳过内容读取。
4. 提供手动完整校验，重新检查源文件内容哈希。

快速检查接受一个限制：内容变化但大小和修改时间同时保持不变时，普通扫描可能无法发现，需要完整校验。

构建规则：

- 源内容变化，包括仅修改标签，重新编码对应歌曲。
- 输出缺失时，根据源文件生成产物。
- 仅编码配置变化时，标记待重建，等待手动启动。
- 源文件仅重命名或移动且内容完全一致时，自动搬迁已有产物并更新记录，避免重新编码。
- 重复扫描或 webhook 不重复排队生成同一个构建目标，也不并行写入同一个输出路径。

新增或修改的源文件至少静默 30 秒后开始转换。转换结束再核对源文件大小和修改时间；若转换期间发生变化，丢弃此次临时产物、重新排队，保留已有输出。这类等待不计入失败次数。

转换先生成临时文件，验证成功后再替换正式产物。转换失败时保留已有可播放文件。

## 普通删除与版本替换

这两个处理分支必须分开。

### 普通源文件删除

- 完整扫描成功且源库可访问后，才判定源文件已删除。
- 保留对应产物，在 MusicForge UI 中明显标记为过期。
- 过期产物继续留在输出目录，也继续出现在 Navidrome 音乐库中。
- 提供手动批量删除过期产物的功能，仅删除登记为本应用产物的文件。
- 删除后通知 Navidrome 扫描，让其移除条目。

### Lidarr 升级替换

- 升级属于版本替换分支。
- 即使源文件名变化，也使用升级事件中的新文件与被替换旧文件列表处理。
- 此次升级的新文件全部转换并验证成功后，自动删除事件列出的旧文件对应产物。
- 转换失败时保留旧产物，等待重试成功。

### 输出编码格式切换

- 手动启动重建后，逐首生成新格式文件。
- 每首新文件验证成功后，删除其旧格式产物。
- 失败时保留旧格式文件供播放。

## 标签与封面

- 保留音频 metadata 和已有 ReplayGain 标签。
- 每首生成的歌曲不重复嵌入封面。
- 优先使用源专辑目录里的 `cover.jpg`、`folder.jpg` 等外置封面。
- 无外置封面时，按曲目顺序从第一首带封面的 FLAC 提取。
- 专辑输出一份 `cover.jpg`。
- 外置封面可以独立更新，无需重新编码歌曲。

## 任务与异常恢复

- Jobs 展示 Pending、Running、Success、Failed，并可查看错误日志。
- 默认同时运行一个 ffmpeg 转换任务，可在 Settings 中调整并发数。
- 首次失败后自动重试两次，总共最多尝试三次，并逐次延长等待时间。
- 三次都失败后标记 Failed，等待单曲或批量手动重试。
- 同一未变化的失败构建目标不会因下一次普通扫描而无限重试。

源库或输出目录暂时不可访问时：

- 显示库离线，暂停受影响的任务，恢复可访问后自动继续。
- 扫描不完整时，不将未扫描到的文件标记为过期。
- 整个存储目录不可用不消耗单曲的三次尝试机会。

容器重启时：

- 成功完成的歌曲跳过，等待中的任务继续。
- 被中断的任务重新检查源状态，从这首歌曲的开头重新编码。
- 清理本应用登记的未完成临时文件，保留原有输出。
- 中断不计入失败次数，恢复粒度为单曲，不做单文件断点续传。

## 扫描触发方式

- 定时扫描，间隔可配置，兜底发现删除、移动和遗漏的变更。
- 手动扫描，包括首次导入、问题排查及完整校验。
- Lidarr webhook，及时扫描受影响的目录并创建转换任务。

## Lidarr 集成

接口：`POST /api/webhook/lidarr`。

- 使用独立集成密钥认证，权限范围为触发源库内的扫描和转换。
- 接收 Lidarr 原生导入/升级载荷：`eventType=Download`，通过 `isUpgrade` 区分升级。
- 从 `trackFiles[].path` 和升级的 `deletedFiles[].path` 定位受影响目录，不依赖额外的专辑路径字段。
- 支持 Lidarr 的连接测试事件，测试成功不创建真实转换任务。
- 支持一组源路径前缀映射，兼容不同的容器挂载路径；非空前缀必须是容器内的绝对路径，保存时校验。
- 映射后的路径仍必须限制在 MusicForge 配置的源根目录内。
- Lidarr 原生 Username/Password 字段支持 HTTP Basic Auth，可用于传递独立 webhook 凭据。

## Navidrome 集成

- 约定 Navidrome 对应音乐库的根目录就是 MusicForge 输出目录，使用相同的专辑相对路径。
- 保留手动刷新按钮。
- 转换或批量删除完成后自动刷新，合并同一批次涉及的目录，避免每首歌触发一次扫描。
- Navidrome 0.59.0 起支持 `startScan` 的 `target` 参数，形式为 `音乐库ID:相对目录`。
- 支持时优先扫描对应专辑目录。
- 整个专辑目录被删除时，扫描最近仍存在的父目录，让 Navidrome 识别删除；根目录目标使用 `音乐库ID:.`，例如 `1:.`。
- 旧版本不支持目录目标时，退回批次结束后的普通扫描。

## 认证

- 一个管理员账号，拥有全部操作权限。
- 本地用户名/密码登录，同时支持原生 OIDC 登录。
- 网页初始化向导创建管理员；首次启动在容器日志显示一次性初始化码。
- 创建账号需要初始化码，创建成功后码失效、向导关闭。
- 本地管理员登录后，在 Settings 配置 OIDC 并绑定自己的身份。
- 仅绑定的 OIDC 身份可登录，绑定使用 `issuer + sub`；username、email 用于展示和操作记录。
- 普通 UI/API 要求管理员登录，没有匿名内网运行模式。
- 不使用 Forward Auth 或 OIDC Proxy 头部认证；Authentik 可作为原生 OIDC 提供方。
- 反向代理负责 HTTPS 和请求转发。

- 本地登录与初始化每个客户端 15 分钟最多允许 10 次凭据失败，成功后清零；OIDC 发起使用独立额度，成功登录后清零，不影响本地恢复和已认证的身份绑定。
- 默认仅按连接地址限流。反向代理部署通过显式可信代理 CIDR 配置读取 `X-Forwarded-For`，从右向左寻找第一个不受信任的地址；不使用该头部提供身份。
- Secret 留空表示保留已有值；提供显式清除 Navidrome 密码和 OIDC 客户端密钥的操作，清除前禁用对应集成。清除 OIDC 密钥须本地登录，并撤销 OIDC 会话、流程和绑定。

## Web UI

技术栈：React、TypeScript、TailwindCSS、shadcn/ui。

- Dashboard：FLAC 数量、输出数量、构建完成比例、最近任务。
- Library：Artist、Album、源状态、输出状态；过期与待重建明显区分，支持批量操作。
- Jobs：任务状态、错误日志、单曲与批量失败重试。
- Settings：源/输出路径、编码格式、模式及其参数、转换并发、扫描间隔、OIDC 与集成配置。
- 登录页面与首次初始化向导。
- 支持英文与简体中文。首次访问按浏览器偏好选择，不支持的语言回退英文；页面提供语言切换，手动选择保存在浏览器中。
- 文案、常见 API 错误、日期与数字随语言变化，切换保留未提交输入及筛选。标签、路径及原始诊断日志保留原文。

## 配置与质量要求

- 监听地址、日志级别等启动配置使用配置文件或环境变量。
- 网页可修改的库路径、编码参数和集成设置保存在 SQLite。
- 每项设置只有一个权威来源，避免配置文件与数据库互相覆盖。
- 提供结构化日志、健康接口、数据库迁移、README 和单服务 Docker Compose 示例。
- 镜像支持 `linux/amd64`、`linux/arm64`。

## 开发环境与发布

- 本地仅进行文件编辑、查看和不涉及编译或依赖下载的静态核查。
- 本地不编译、不安装或下载依赖、不构建 Docker 镜像。
- 依赖安装、编译、可执行测试与验证、镜像构建均由 GitHub Actions 执行。
- 依赖锁文件通过 GitHub Actions 生成或更新。
- PR 和主分支提交运行 CI 验证，不发布容器镜像。
- 推送版本标签，例如 `v0.1.0`，在 CI 验证成功后发布多架构镜像到 GHCR。
- 发布对应版本的镜像标签，稳定版本同时更新 `latest`；预发布版本不更新 `latest`。
